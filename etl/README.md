# Azure ETL for the SAP S/4HANA Retail data migration

This folder contains a working reference implementation of the migration pipeline described in
[docs/10-data-migration-azure-etl.md](../docs/10-data-migration-azure-etl.md). The pipeline extracts legacy
merchandising and finance data with **Azure Data Factory**, cleanses and transforms it in **Azure Databricks**
(bronze → silver → gold on **ADLS Gen2**), records data quality and reconciliation in an **Azure SQL** control
database, and loads the gold data into the **SAP S/4HANA Migration Cockpit staging tables in SAP HANA**. The
Migration Cockpit then performs the final transfer into S/4HANA.

## Folder map

| Path | Content |
|---|---|
| `infra/main.bicep` | ADLS Gen2 (bronze/silver/gold/archive), Data Factory + self-hosted IR, Databricks (premium) + access connector, Azure SQL (serverless), Key Vault, Log Analytics, RBAC |
| `adf/` | Data Factory linked services, datasets and pipelines (`pl_00_master_migration`, `pl_10_extract_legacy`, `pl_20_transform`, `pl_30_load_hana_staging`, `pl_40_reconcile`) – generated by `adf/generate_adf.py` |
| `databricks/` | Notebooks: `01_bronze_to_silver`, `02_silver_to_gold` (+ DQ gate), `03_load_hana_staging` (JDBC to HANA), `04_reconcile_target` |
| `src/retail_etl/` | Python library shared by notebooks and tests: transforms per migration object, GS1 checks, reconciliation, HANA staging loader |
| `config/` | `mapping_rules.yaml` (value mappings, G/L account mapping), `staging_tables.yaml` (gold → generated staging table names) |
| `sql/azure_sql/` | Control DB: object catalogue, run log, DQ results, reconciliation, value mappings, readiness view |
| `sql/hana/` | DEV-only stand-in staging tables for sandbox testing |
| `sample_data/legacy/` | Fictitious legacy extract with deliberate defects (`generate.py`) |
| `sample_output/` | Gold files, DQ findings, reconciliation and control totals produced from the sample |
| `tests/` | Unit and end-to-end tests (`pytest`) |

## Run locally

```bash
pip install -r etl/requirements.txt
python etl/sample_data/generate.py                                   # recreate the sample legacy extract
cd etl && PYTHONPATH=src python -m retail_etl.pipeline --source sample_data/legacy --out sample_output
python -m pytest                                                     # 13 tests
```

## Legacy extract layout (silver input)

| Object | Columns |
|---|---|
| stores | store_id, store_name, store_type (STORE / DC / WEB), street, city, state, zip, country, open_date |
| vendors | vendor_id, name, street, city, state, zip, country, tax_id, bank_routing, bank_account, payment_terms |
| items | style, style_desc, dept, class, color, size, upc, unit_cost, retail_price, vendor_id |
| onhand | store_id, upc, qty_on_hand, unit_cost (after the cutover count) |

| Gold object | Fields | Migration Cockpit object |
|---|---|---|
| site | WERKS, NAME1, VLFKZ, PROFILE, BUKRS, VKORG, VTWEG, PRCTR, address, EROED | Site (retail) [VERIFY] |

| sales_price | KSCHL=VKP0, VKORG, VTWEG, MATNR, KBETR, KONWA, KPEIN, KMEIN, DATAB, DATBI | Condition record for pricing in sales |

> Staging table names and exact staging fields are generated per Migration Cockpit project and release.
> Download the staging template of each migration object, compare it with the gold layout above, and record the
> generated table names in `config/staging_tables.yaml` before Mock 1. Items marked [VERIFY] must be confirmed.

## Key controls

* **No silent drops** – every source row is either in gold or rejected with an ERROR finding (`source_vs_gold`).
* **Inventory = G/L** – initial stock (561) value equals the legacy inventory balance; the migration clearing
  account 39990000 nets to zero after the stock and G/L balance loads (`cross_object_checks`).
* **DQ gate** – ADF stops before the HANA load if reconciliation fails or blocking ERRORs remain. Mock loads run with `allow_dq_errors = true` (rejected rows are reported to data owners); the cutover run requires zero open ERRORs.
* **Repeatable mocks** – staging tables are truncated per object; every run has a `run_id` (MOCK1 … CUTOVER).
* **Secrets** – only in Key Vault; private endpoints for lake, SQL, Key Vault and Databricks.
